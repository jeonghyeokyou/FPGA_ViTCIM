# ViT-Base layer 0 C 프로그램 정리 (QKV → attention 전체)

대상 보드: ZCU102 (PetaLinux, PS = Cortex-A53, PL0 = 214.264286 MHz)
PL: share3 RTL + ch0remap + ch2lin (bitstream `vit_base/l2_bb_d.bit.bin`, 2026-10-30)
BB: MAC BB (`blackbox_ip`, ch1)와 vector BB (`blackbox_nl`, ch2)는 계산하지 않고 Golden을 그대로 내보냄
근거 태그: [보드 확인] [시뮬레이션 확인] [RTL 확인] [계산] [추론] [미확인]

## 1. 보드 폴더 구조 (유지하기로 한 구조)

```
~/vit_base/
├─ data/        vit_golden_gen.py (MXFP4) 출력 전체 (파일 23개 + meta.json)
├─ log/
├─ vit_c/       C 소스 (파일을 바꾸거나 추가하면서 진행, 새 폴더는 만들지 않음)
├─ vit_main     실행파일 (vit_c에서 -o ../vit_main 으로 빌드)
├─ vit_dbg      실행파일
├─ l2_bb_d.bit.bin, l2_bb256_214.dts / .dtbo
```

빌드 (`vit_c` 안에서 실행):
```
gcc -O2 -std=gnu11 -Wall -Wextra -o ../vit_main \
    vit_main.c vit_hw.c vit_ops.c attn_ops.c mxfp4.c -lm
gcc -O2 -std=gnu11 -Wall -Wextra -o ../vit_dbg \
    vit_dbg.c vit_hw.c vit_ops.c attn_ops.c mxfp4.c \
    dbg_common.c dbg_qkv.c dbg_attn.c -lm
```

실행:
```
sudo ./vit_dbg  --data ./data --op qkv|attn|oproj [--head H] [--tile J] [--map]
sudo ./vit_main --data ./data [--heads N]
```

## 2. 소스 구성

| 파일 | 역할 | 상태 |
|---|---|---|
| `vit_hw.h/.c` | 하드웨어 계층: `/dev/mem` mapping, L2 명령 FIFO, CDMA queue, MAC BB, vector BB, L2 window(PS 읽기/쓰기), 시간 집계 | QKV 버전에 vector BB·ch2 명령·시간 집계 추가 |
| `vit_ops.h/.c` | QKV projection 한 head (`qkv_proj_head`), L2 배치(`QKV_LAYOUT_DEFAULT`), 파일 로드 | QKV 버전 그대로 |
| `attn_ops.h/.c` | attention 흐름: QKᵀ, softmax, AV, out proj, PS 작업(MXFP4·residual), L2 배치 v2 | 새 파일 |
| `mxfp4.h/.c` | PS MXFP4 양자화, BF16 변환 | 새 파일 |
| `vit_main.c` | 전체 흐름 실행 + 최종 출력 검사 + 연산별 시간·cycle 표 | 새로 작성 (이전 QKV 전용 main을 대체) |
| `vit_dbg.c` | dbg 진입점 (`--op qkv / attn / oproj`) | `--op attn`, `--op oproj`, `--tile` 추가 |
| `dbg_common.h/.c` | 검사 결과 집계 (C1~C6), 비교·poison 도우미 | C6 추가 |
| `dbg_qkv.h/.c` | QKV 한 head의 호출별 검사, `--map`, `--trace` | QKV 버전 그대로 |
| `dbg_attn.h/.c` | attention 한 head / out proj 한 tile의 호출별 검사 | 새 파일 |

설계 원칙: main과 dbg는 같은 ops 코드를 실행합니다. main은 hook 없이, dbg는 hook 지점에 검사를 붙입니다. 그래서 하드웨어로 나가는 명령 순서가 둘이 같습니다.

## 3. 하드웨어 계층 (`vit_hw`)

### 3.1 주소와 접근

| 항목 | 내용 |
|---|---|
| L2 줄 번호 c | 15bit = {group 3b, quad 2b, row 10b}. 한 줄 = 256bit = 32 B, 전체 32,768줄 = 1 MiB |
| PS 주소 (ch0remap) | 0xA000_0000 + 32c (줄 안의 lane은 +8·lane) |
| L2 window | Device 메모리로 mapping, 64bit 단위 읽기/쓰기 (`hw_l2_read`, `hw_l2_write`) |
| CDMA | DDR ↔ L2, 비동기 queue (`hw_cdma_submit / service / drain / copy`) |
| DMA buffer | 예약된 DMA heap에서 할당 (`hw_buf_alloc`), cache sync는 `hw_cache_sync` |
| PL0 clock | 실행 시 Linux `clk_summary`에서 읽어 확인 |

### 3.2 L2 명령 (command FIFO에 64bit 명령을 넣고 CMD_DONE 증가를 기다림)

| 명령 | 함수 | 필드 |
|---|---|---|
| ch1_in LOAD (L2 → L1) | `cmd_x_load(c, n, l1_row)` | op 001, L2 [54:40], n−1 [39:29], L1 [28:18] |
| ch1_in STORE (L1 → L2) | `cmd_x_store(l1_row, n, c)` | op 010, L2 [55:41], n−1 [40:27], L1 [23:13] |
| ch1_wgt LOAD (L2 → WMEM) | `cmd_w_load(c, n, w_row)` | op 101, L2 [53:39], n−1 [38:29], WMEM [28:19] |
| ch1_wgt STORE (WMEM → L2, dbg용) | `cmd_w_store` | op 110 |
| ch2_in LOAD (L2 → vector 입력 메모리) | `cmd_v_load(c, n, v_row)` | op 011, L2 [53:39] 15b, n−1 [38:25], PE [24]=0, row [23:10] |
| ch2_in STORE (vector BB → L2) | `cmd_v_store(c, H, W)` | op 100, [59:58]=10, L2 [54:40] 15b, H [39:30], W [29:20] |

ch2 STORE beat 주소: c = start + w + h·W + cg·H·W, cg = 2·jp + col (ch2lin) [RTL 확인, 시뮬레이션 확인: T19~T21]

### 3.3 MAC BB (ch1)

| 함수 | 동작 |
|---|---|
| `hw_bb_gold_load(lines, n)` | Golden BRAM에 n줄(≤256) 주입. 256bit window(0x80~0x9C) + GCOMMIT |
| `hw_bb_run(in_base, in_len, w_base, w_len, out_base, out_len, inject, &cycles)` | L1 입력 행, WMEM 행을 읽고 Golden을 L1 출력 행에 씀 |
| cycle | CYCLES = in + w + out + 9 [보드 확인] |
| INJECT | Golden beat 0의 bit 0을 뒤집음 (C5 검사용) |

### 3.4 vector BB (ch2) — attention 단계에서 추가

| 레지스터 | 주소 | 내용 |
|---|---|---|
| CTRL2 | 0x120 | bit0 START, bit1 INJECT, bit2 HS, bit3 PREC |
| IN2 | 0x124 | {in_len, in_base} |
| SHAPE2 | 0x128 | {nb[30:24], h[19:10], w[9:0]} |
| STATUS2 | 0x130 | {err_start_busy, dbg_valid, done, busy} |
| CYCLES2 | 0x140 | 실행 clock 수 |
| GADDR2 / GCOMMIT2 | 0x144 / 0x148 | Golden 주입 |
| WGT2 | 0x14C | weight 메모리 범위 (softmax에서는 0) |
| DBG2 / DBG2_DATA | 0x150 / 0x160~ | 입력·weight 메모리 한 행 읽기 (dbg용) |

| 함수 | 동작 |
|---|---|
| `hw_bb2_gold_load` | vector BB Golden 주입 (window 공유) |
| `hw_bb2_run_store(in_base, in_len, c, H, W, inject, &cycles)` | ch2_in STORE 명령을 먼저 넣고 → START → BB done 대기 → STORE 완료(CMD_DONE) 대기 |
| `hw_bb2_dbg_read(sel, row, line)` | DBG2로 입력(0)·weight(1) 메모리 한 행 읽기 |
| cycle | CYCLES2 = in + w + 3·beats + 6 [시뮬레이션 확인, 보드 확인: 994 / 370] |

메모리 크기: 입력 2,048행, weight 512행, Golden 256줄. 출력은 L1을 거치지 않고 ch2_in STORE로 L2에 바로 씀. [RTL 확인]

### 3.5 시간 집계 (attention 버전에서 추가)

- `hw_op_begin(h, op)` / `hw_op_end(h)`로 현재 연산을 지정합니다.
- hw 함수들이 자기가 쓴 시간을 그 연산에 더합니다.

| 종류 | 들어가는 시간 |
|---|---|
| PK_CMD | L2 LOAD/STORE (`hw_cmd_run`) |
| PK_GOLD | Golden 주입 (BB 모사에만 있는 작업) |
| PK_BB | BB START부터 done까지 (ch2는 STORE 완료까지) |
| PK_DMA | CDMA 대기 |
| PK_PS | PS 계산 (MXFP4, residual) |
| bb_cycles | CYCLES / CYCLES2 레지스터 합 |

## 4. QKV 단계 (`vit_ops`, 이전 버전에서 완성)

### 4.1 L2 배치 (`QKV_LAYOUT_DEFAULT`)

| 데이터 | 버퍼 A | 버퍼 B |
|---|---|---|
| X (197 토큰 × 768, 토큰당 12줄) | 0x0000 ~ 0x093B (2,364줄) | 공용 |
| W (head 하나: Q, K, V × 64열 × 12줄 = 2,304줄) | 0x0C00 | 0x2400 |
| Y (Q, K, V 각 788줄, 토큰당 4줄) | 0x1800 / 0x1C00 / 0x2000 | 0x3000 / 0x3400 / 0x3800 |

### 4.2 한 head의 명령 순서

```
P = Q, K, V 각각:
  WLOAD  W_P 768줄 → WMEM 0
  group 0 (토큰 0~127) / group 1 (토큰 128~196):
    LOAD   X 12·nt줄 → L1 0
    BB     토큰 64개 (in L1 0+768, w 0+768, out L1 1536+256)
    BB     나머지   (in L1 768+12·n2, out L1 1792+4·n2)
    STORE  L1 1536, 4·nt줄 → Y_P + 4·g0
```

- head당 L2 명령 15개(WLOAD 3 + LOAD 6 + STORE 6), BB 호출 12번.
- A/B 겹치기 모드: head h를 계산하는 동안 CDMA가 W(h+1)를 다른 버퍼에 쓰고, Y(h−1)를 DDR로 꺼냄.
- 기준: 동시에 도는 작업은 서로 다른 half(64 KiB)를 씀(X3 규칙).

### 4.3 QKV 보드 결과 [보드 확인]

| 항목 | 결과 |
|---|---|
| ch2lin bitstream + MXFP4 데이터, A/B 겹치기 | 12 heads PASS, 28,368줄 불일치 0, 73.1 ms (head당 약 6.0 ms) |
| data md5 | x `dddb8f19…`, w `de09914f…`, y_golden `f68a852a…` |

## 5. attention 단계 (`attn_ops`)

### 5.1 데이터 형식

| 항목 | 결정 |
|---|---|
| MAC 입력 | MXFP4 (OCP MX v1.0, 블록 32개, E8M0 scale, E2M1 원소) |
| 그 외 | BF16 |
| scale 위치 | DDR에만 둠 (결정 (가), 2026-10-30). BB 모델은 scale을 읽지 않음 |
| padding | S, A 행은 208칸 (197 + 0 × 11) = 13줄. A FP4 행과 Vᵀ 열은 256칸 (197 + 0 × 59) = 4줄 |

### 5.2 L2 배치 v2

| 데이터 | c 범위 | 크기 |
|---|---|---|
| Q MXFP4 (12 head) | 0x4000 + 197h | head당 197줄 |
| K MXFP4 (12 head) | 0x493C + 197h | head당 197줄 |
| Vᵀ MXFP4 (12 head) | 0x5278 + 256h | head당 256줄 |
| S → A (같은 자리), b = h % 2 | 0x0000 / 0x1000 | 2,561줄 |
| A MXFP4 | 0x0C00 / 0x1C00 | 788줄 |
| O BF16 | 0x2000 / 0x2800 | 788줄 |
| O concat MXFP4 (줄 12t + h) | 0x0000 | 2,364줄 |
| W_O tile, b = j % 2 | 0x4000 / 0x4800 | 768줄 |
| Y tile j | 0x1000 + 0x400·j | 788줄 |
| dbg 전용 scratch | g6 (0x6000 ~ 0x6A01) | main은 쓰지 않음 |

### 5.3 연산별 명령 순서

| 연산 | 함수 | 순서 |
|---|---|---|
| QKᵀ | `at_qkt_head` | LOAD Q_h 197 → L1 0, WLOAD K_h 197 → WMEM 0, 11번 [BB(in L1 19r+19, w 0+197, out L1 1536+247) → STORE → S_b + 13·19r]. 마지막은 7행(91줄) |
| softmax | `at_softmax_head` | ch2 LOAD 152행(1,976줄) → 입력 메모리 0, 8번 [Golden A 247줄 → vector BB(in 13r+247) → ch2 STORE를 같은 S 자리에]. 이어서 45행(585줄)을 LOAD하고 3번 반복 (19, 19, 7행) |
| AV | `at_av_head` | LOAD A4_b 788 → L1 0, WLOAD Vᵀ_h 256 → WMEM 0, 4번 BB(토큰 64/64/64/5, in L1 4t0+4nt, w 0+256, out L1 1024+4t0) → STORE 788 → O_b |
| out proj | `at_oproj_tile` | WLOAD W_O tile 768 → WMEM 0, 이후 QKV와 같은 패턴 (O concat을 X 자리에) → STORE → Y tile j |

### 5.4 PS 작업

| 함수 | 입력 → 출력 | 블록 방향 |
|---|---|---|
| `ps_mx_qkv` | Y_h (Q, K, V BF16) → Q, K FP4 (토큰당 1줄) + Vᵀ FP4 (d당 4줄) | Q·K: 토큰마다 64 = 2블록. Vᵀ: d마다 토큰 256 = 8블록 |
| `ps_mx_a` | A BF16 (2,561줄) → A FP4 (788줄) | 행마다 256 = 8블록 |
| `ps_mx_o` | O_h BF16 → O concat의 줄 12t + h | 토큰마다 64 = 2블록 (head마다 따로 가능) |
| `ps_residual` | R = BF16(f32(h_in) + f32(Y)) | – |

MXFP4 규칙 (`mxfp4.c`, Python 생성기와 같은 규칙)
- X = floor(log2(블록 max|v|)) − 2. [−127, 127]로 제한하고, 모두 0이면 −127. scale byte = X + 127.
- 원소 = v / 2^X → E2M1 경계값 비교 (0.25, 0.75, 1.25, 1.75, 2.5, 3.5, 5.0). 동률이면 가수 0 쪽. 6을 넘으면 6. −0은 없음.
- packing: 원소 2i → byte[3:0], 2i+1 → byte[7:4].

### 5.5 vit_main 흐름 (순차 실행)

```
X → L2
head 0..11 : W(h) → L2 / poison Y / QKV(h) / Y → DDR / PS MXFP4 / Q,K,Vᵀ → L2 g4~g5
head 0..11 : poison S, O / QKᵀ / softmax / A → DDR / PS MXFP4 / A4 → L2 / AV / O → DDR / PS concat MXFP4
12 head 후 : O concat → L2 / poison Y tile / tile 0..11 [W_O → L2, out proj] / Y → DDR / PS residual
최종 검사 → 시간 표
```

- 연산마다 시간을 따로 재려고 순차로 실행합니다. A/B 겹치기와 3단 pipeline은 이 버전에 넣지 않았습니다.
- `--heads N`(N < 12)이면 concat 앞에서 멈춥니다.
- DMA buffer: 쓰기용 75,648 B, 읽기용 81,952 B, poison용 81,952 B.

## 6. 검증 체계

### 6.1 vit_main 최종 검사 (출력만)

| 검사 | 비교 대상 |
|---|---|
| BB 출력 (L2 → DDR) | Y(QKV) == y_golden, A == a_golden, O == o_golden, Y(out proj) == yo_golden |
| PS 결과 | Q, K, Vᵀ, A, O concat의 MXFP4 코드와 scale == Python 파일, R == r_golden |

BB가 Golden을 그대로 내보내므로, 입력이 틀려도 main은 잡지 못합니다. 입력 검사는 dbg가 맡습니다.

### 6.2 vit_dbg 검사 항목

| 검사 | 내용 |
|---|---|
| C1 | DDR → L2 (CDMA) 후 PS로 되읽어 비교 |
| C2 | BB 입력: MAC은 L1·WMEM 행을 STORE로 scratch에 꺼내 비교. vector는 LOAD 직후 DBG2로 입력 메모리를 읽어 비교 |
| C3 | CYCLES: MAC은 in + w + out + 9, vector는 in + 3·out + 6 (정확히 일치해야 함) |
| C4 | L1 출력, L2 출력, DDR 복사본 == Golden. 출력 영역을 먼저 poison. guard 줄 유지 확인. softmax는 다음 행이 아직 S인지도 확인 |
| C5 | INJECT 1bit 오류를 정확히 잡는지 (MAC, vector) |
| C6 | PS 결과(MXFP4 코드·scale, residual) == Python 파일 |

| 모드 | 범위 |
|---|---|
| `--op qkv --head H` | QKV 한 head. `--map`, `--trace T --p Q/K/V` 지원 |
| `--op attn --head H` | QKV(검사 없음) → C6 → C1 → C5 → QKᵀ·softmax·AV 호출별 C2/C3/C4 → A·O 양자화 C6 |
| `--op oproj --tile J` | oc_fp4.bin을 L2에 올리고 tile J를 호출별 검사 → Y tile C4 → 그 64열의 residual C6 |

### 6.3 보드 밖 사전 검증 [시뮬레이션 확인]

- 명령 필드를 따로 해석하는 소프트웨어 하드웨어 모델(x86)에 실제 데이터(`vit_l0_mx`)를 넣어 main과 dbg를 모두 PASS.
- 고장 주입 결과
  - 입력 쪽 고장(Q LOAD 주소, Vᵀ WLOAD, ch2 LOAD 길이)은 dbg C2만 잡음.
  - 출력 쪽 고장(AV STORE, softmax STORE 주소)은 main과 dbg가 모두 잡음.
- aarch64 cross-compile: `-Wall -Wextra -Wconversion -Werror` 경고 없음.

## 7. 보드 결과 (2026-10-30) [보드 확인]

### 7.1 dbg

| 실행 | 결과 |
|---|---|
| `--op attn --head 0` | C1 6, C2 32, C3 26, C4 54, C5 4, C6 10 PASS, FAIL 0 |
| `--op oproj --tile 0` | C1 2, C2 8, C3 4, C4 7, C6 1 PASS, FAIL 0 |

보드에서 처음 확인된 것
- PS C 양자화가 Python 생성기와 bit 단위로 같음 (Q, K, Vᵀ, A, O concat).
- ch2lin LOAD: 1,976줄(g0 q0 → q1 경계를 넘음)과 585줄 모두 S와 일치.
- ch2lin STORE: 11번 모두 A가 S 자리에 덮어써지고, 다음 행은 S 그대로이며, guard 줄(0x7FFF, 0x0A01)도 유지됨.
- vector CYCLES2 994 / 370이 시뮬레이션과 같음 (L2 ready 대기 없음).
- MAC cycle: QKᵀ 472 / 304, AV 777 / 305, out proj 1801 / 857.

```
├─ Golden 주입 265.8 ms (69%)   BB 모사 전용. 실제 IP에는 없음
└─ 나머지 120.8 ms
   ├─ PS 계산 113.7 ms (94%)    MXFP4 양자화 + residual
   └─ PL 쪽 7.1 ms (6%)        L2 명령 + BB + CDMA
```

- BB clk는 BB 모델이 입력을 읽고 Golden을 쓰는 clock 수입니다. 실제 MAC 연산 시간이 아닙니다.
- BB의 wall 시간이 BB clk보다 약 2배 긴 것은 PS polling 시간 때문입니다. [계산]
